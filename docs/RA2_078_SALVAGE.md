# Media startup, completion and foreground recovery

The accepted producer contract comes from RA2 075. The implementation uses 076's compact UI base. RA2 077 is a physically rejected donor, not a branch base. Its changes are independently assessed below. Classification A means safe and required; B means safe and optional; C means correlated with the rejected candidate and excluded; D means unresolved and excluded. A deterministic defect is not proof that it caused the reported iPhone symptom.

## Additional startup repair

The first dynamic refill occurs before a shared worklet reader exists. Before that handoff the guest needs the static renderer's consumed cursor. Stream-trace-only publication occurs at Create/Lock/Unlock; GetCurrentPosition is deliberately not a diagnostic publication site. A wall-time model can therefore claim a segment was consumed while the newly running AudioContext clock is still pinned, and the reader can subsequently appear to jump back to segment zero.

`audio.ts` publishes a static cursor immediately after a successful source start and every 30ms while that source exists. `vmClient.ts` sends only scalar cursor metadata with the current buffer owner. `vmProtocol.ts` carries `renderClockProgressing`; `ProxyAudioSink.getConsumerCursor` does not extrapolate a production sample whose renderer clock has not moved. The worklet reader remains authoritative after handoff. The timer has the sink's destruction owner and is suppressed during pending recovery. No PCM or guest memory crosses this observation path.

This is an A repair: it is necessary for the stronger startup gate. The bridge smoke must observe each first consumed segment and all subsequent refills, not merely a final completion. The repair does not modify DirectSound's accepted producer cache bypass. Whether this deterministic race caused the rejected physical 077 cameo loop has not been established.

## Separate gates

- `specialMediaAudio.e2e.test.ts` and `specialMediaAudioBrowserSmoke.mts`: accepted producer startup, cache bypass and source/refill progress.
- `specialMediaCompletion.e2e.test.ts`: two sequential events through the actual worker proxy; Stop/reset, final refill, Release, stale-reader rejection, guest simulation/input/presentation progress.
- `specialMediaCompletionBrowserSmoke.mts`: real WebAudio and worker-message protocol with two starts, each consumed segment visible, increasing source/refill positions, complete retirement, and frame/input progress after each event. Synthetic media fixtures contain no owner assets; they do not prove full campaigns or speech content.
- `audioRecovery.test.ts` and lifecycle coordinator tests: authoritative generation, stale async rejection, renderer progress, successful pending-state clearance and genuine failure closure.
- `audioGestureRecoveryBrowserSmoke.mts`: real trusted input, same/fresh context policies, three short cycles, seven-second and thirty-second cycles; one live renderer and no retained retired contexts.
- `audioSilentBoundary.test.ts`, `audioLifecycleBrowserSmoke.mts` and `audioReaderBrowserSmoke.mts`: coherent cursor retirement, silent acknowledgement, real processor lifetime and non-resurrection.
- `touchUiBrowserSmoke.mts`: trusted 400ms long-press produces Esc only for active skippable briefing state; normal long-press stays right-click; keyboard Esc and touch rail keys remain available.

The managed Apple workflow runs both media browser gates alongside the full source suite, lifecycle/browser gates, simulator host tests and unsigned ARM64 packaging. Public proof must contain zero owner Data files. The private original-DLL and campaign routes are read-only diagnostic supplements; an automatically unreproduced physical route must be reported explicitly.
